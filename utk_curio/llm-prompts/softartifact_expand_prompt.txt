You receive a source document (plain text, split into numbered chunks), an existing Curio dataflow (nodes and edges with their ids), and must propose ADDITIONS that extend the workflow based on material in the document that is not yet represented.
Your job is to identify gaps, alternatives, follow-on analyses, or what-if branches suggested by the document and express them as new nodes and edges that plug into the existing graph.
OUTPUT FORMAT (strict)
- Output JSON only. No markdown fences, no commentary, no prose outside the JSON object.
- Top-level shape:
  {
    "rationale": "<1-3 sentences explaining what you are adding and why, referencing the document>",
    "dataflow": {
      "name": "<same name as the current dataflow unless the document clearly warrants a rename>",
      "nodes": [ ... only NEW nodes ... ],
      "edges": [ ... only NEW edges ... ]
    }
  }
SCOPE RULES
- Return ONLY new nodes and new edges. Do NOT repeat or rewrite existing nodes from the current dataflow.
- Every new edge must connect to at least one existing node id from the provided current dataflow.
- New edges may connect: existing → new, new → existing, or new → new (as long as the subgraph attaches to the existing graph).
- Do NOT change or re-id existing nodes.
WHAT-IF AND ALTERNATIVES
- When the document describes alternative scenarios, optional paths, competing hypotheses, or parameter choices, prefer introducing a FLOW_SWITCH node to branch the flow rather than duplicating entire pipelines.
- Use FLOW_SWITCH when the document explicitly contrasts options (e.g. "option A vs option B", "with vs without filter", "baseline vs intervention").
NODE RULES (for each NEW node)
- "id": a new UUID v4 string (never reuse ids from the current dataflow or from examples).
- "type": one of the valid node types listed below.
- "goal": a specific subtask in at most 40 words, grounded in the document. Avoid generic phrases.
- "in": expected input data type.
- "out": expected output data type.
- "citations": array of chunk indices (integers) from the provided document that justify this addition.
FORBIDDEN
- Do NOT include "content", "code", "x", "y", "output", or implementation text.
- Do NOT invent node types outside the valid list.
- Do NOT return the full merged graph — only the delta (new nodes and edges).
TYPE COMPATIBILITY
- Respect input/output types in the registry below.
- New edges must respect type compatibility between connected nodes (existing or new).
