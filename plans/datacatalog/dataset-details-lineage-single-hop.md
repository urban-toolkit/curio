# Implementation Memo: Trace full upstream chain (source datasets) for computed datasets

**Status:** Proposed (memo only — no code written) · **Branch:** `datacatalog` · **Author:** Karla
**Area:** `services/datasetLineage` (frontend resolver), `components/datasets/catalog/DatasetDetailPanel` (render), `backend/app/datasets` (upstream source-dataset resolution) + tests

> **Split note.** This memo covers the **"single-hop only"** half of the original lineage
> investigation. The companion issue — *wrong/missing producer record when a dataset is opened
> from a dataflow that only imported it* — is tracked and implemented separately in
> [`dataset-details-lineage-cross-dataflow.md`](./dataset-details-lineage-cross-dataflow.md).
> That fix surfaces the **authoritative producer node** (and its producing dataflow) on the
> Dataset Details page. This memo builds on it to trace the **upstream source datasets** feeding
> that producer.

---

## 1. Problem Statement

**Current behavior — lineage stops at the immediate producer node.** The Dataset Details
"Generated by" section reports only the dataset's own producer node and goes no further. It
never surfaces the **source datasets** that feed that producer, so a computed dataset derived
from earlier computed outputs shows an incomplete, single-hop upstream.

**Concrete repro (whatif specs).** The `whatif` dataflow graph is:

```
whatif-data ──▶ whatif-pool ──▶ whatif-baseline-compute ──▶ whatif-baseline-map
(autk-grammar)  (data-pool)  └─▶ whatif-modified-compute ──▶ whatif-modified-map
```

`computed.whatif-modified-compute@1` is produced by node `whatif-modified-compute`, which is
fed — through the `whatif-pool` data-pool **carrier** — by `whatif-data` (producer of
`computed.whatif-data`). The details page reports only *"Generated by whatif-modified-compute"*
and stops. It never shows the upstream **source dataset** `computed.whatif-data` or the upstream
node chain.

**Root cause (confirmed).**
`selectDatasetUpstreamLineage()` —
`utk_curio/frontend/urban-workflows/src/services/datasetLineage/datasetLineageResolver.ts:314-343`
— resolves `generatingNode` from `dataset.producerNodeId` only and returns
`sourceDatasets: []` (`:339`, commented *"Reserved for the source-dataset phase"*). It never
walks `edges` backward from the producer node through carrier nodes (`data-pool` /
`data-loading`) to the upstream producer nodes and their datasets. The backend likewise exposes
a **downstream** cross-dataflow resolver (`GET /datasets/<id>/usage` →
`_dataset_consumer_nodes_in_spec()` in
`utk_curio/backend/app/datasets/services/catalog_listing.py:355-431`) but **no upstream
source-dataset analog**. Manifests carry no lineage; the spec graph is the only source of truth.

**Expected behavior.**
- Upstream lineage traces the **full chain**: producer node → upstream carriers
  (`data-pool` / `data-loading`) → upstream producer nodes → their **source datasets** —
  including across dataflows and through chained computed-from-computed datasets.
- The page shows a **"Derived from (N)"** group listing each upstream source dataset with its
  producing node and dataflow.

**Why it matters.** Single-hop upstream understates provenance for chained dataflows (the whole
point of lineage for computed datasets) and makes it impossible to see where a derived dataset's
inputs actually came from.

## 2. Scope

**In scope**
- Backward carrier-walk to resolve **source datasets** — a backend analog of
  `_dataset_consumer_nodes_in_spec()` (an *upstream* resolver), surfaced via a
  `GET /datasets/<id>/lineage` endpoint or enriched item, consumed by a
  `useDatasetUpstreamLineage(datasetId)` hook (analogous to `useDatasetDataflowUsage`,
  `DatasetDataflowUsage.tsx:18-41`).
- Populate `DatasetUpstreamLineage.sourceDatasets` (`datasetLineageTypes.ts:45-53`, currently
  hardcoded `[]`) in `selectDatasetUpstreamLineage`/`selectDatasetLineage`.
- Render a **"Derived from (N)"** block in `DatasetDetailPanel` (`UpstreamCards`,
  `LineageMainSection`).
- Reuse the carrier-walk logic factored out of `selectDatasetDownstreamUsage:245-266`.
- Tests (see §7).

**Out of scope**
- The authoritative-producer fix (companion memo) — this builds on it; do not duplicate it.
- Downstream usage / `/usage` endpoint behavior (reuse the pattern only).
- Persisting lineage into manifests — keep the spec as the source of truth, resolved at query
  time.

## 3. Recommended Implementation Approach

1. **Backend upstream resolver.** Add an *upstream* analog to `_dataset_consumer_nodes_in_spec`
   in `catalog_listing.py`: given a `datasetId`, find its producing dataflow + node, walk
   `edges` **backward** from `producerNodeId` through carrier nodes (`data-pool` /
   `data-loading` — reuse the carrier classification used downstream) to upstream producer nodes,
   and map them to their `datasetId`s (`computed.<nodeId>`). When an upstream carrier loads a
   dataset persisted by another dataflow, recurse one authoritative hop (bounded — cycle guard +
   depth cap) so chained cross-dataflow lineage is captured. Expose via
   `GET /datasets/<id>/lineage` returning `{ sourceDatasets: [{datasetId, title?, producedByNode?, dataflowId?, dataflowName?}] }`.
2. **Frontend types.** Make `DatasetUpstreamLineage.sourceDatasets` actually populated; extend
   `DatasetLineageDatasetRef` (`datasetLineageTypes.ts:13-16`) with optional `producedByNode`,
   `dataflowId`, `dataflowName`.
3. **Frontend resolver.** In `selectDatasetUpstreamLineage`, populate `sourceDatasets` by
   walking `edges` backward from `producerNodeId` through carriers (shared helper factored from
   the downstream carrier walk) and/or from the backend upstream payload on canvas-less surfaces.
   Thread the backend payload through `selectDatasetLineage` + `useDatasetLineage` the way
   backend **downstream** is already merged in `DatasetDetailPanel.tsx:271-277`.
4. **Render.** Add a **"Derived from (N)"** block above *"Consumed by"* in `LineageMainSection`,
   styled consistently with the existing cards; cross-dataflow sources labeled with their
   dataflow name.

Keeps UI render, pure selectors, data hooks, and backend spec-traversal separated; reuses the
proven carrier-walk; adds no persisted state.

## 4. Data and State Handling

- **Source of truth:** spec `dataflow.datasets[]` + `nodes`/`edges`; computed at query time.
- **Derived value:** `sourceDatasets[]` via backward carrier walk, bounded recursion across
  dataflows.
- **Live vs. backend merge:** prefer live-canvas resolution when upstream nodes are on the open
  canvas; fall back to the backend upstream payload otherwise (mirror downstream merge).
- **Loading/empty/error:** pending → skeleton; error → fall back to live-canvas + flag partial;
  empty upstream (true source/root dataset) → origin label only.
- **Avoid stale/flicker:** memoize the upstream payload by `datasetId`; recompute resolver only
  when `dataset`/`nodes`/`edges`/exec-status/payload change.

## 6. Edge Cases

- **Chained computed → computed across dataflows:** recurse one authoritative hop per source;
  **cycle guard** (visited-set on `datasetId`) + **depth cap**; flag partial when capped.
- **Carrier with no upstream edge** (freshly dropped, unconnected): no source datasets.
- **Producer/upstream node deleted or not on any canvas:** use backend-resolved name/type; mark
  `unresolved` when the producing dataflow no longer lists the node.
- **True source / root dataset:** no upstream chain; origin label only — do not fabricate.
- **Bundle / multi-output producer:** map sources by the correct `datasetId`, not just
  `computed.<nodeId>`.
- **Canvas-less catalog page:** upstream entirely from backend payload; flag partial if
  unresolved.
- **Duplicate refs across many dataflows:** dedupe sources; don't double-list.
- **Malformed/missing edges or nodes:** tolerate; never throw from a pure selector.

## 7. Testing Strategy

**Backend (pytest, near `tests/test_datasets/test_dataset_usage.py`)**
- `computed.whatif-modified-compute` → `sourceDatasets` includes `computed.whatif-data` via the
  `whatif-pool` carrier walk.

  Flow A.
- Chain cycle / depth cap returns partial without hanging.

**Frontend unit (resolver)**
- Builds `sourceDatasets` from edges + carriers; falls back to backend payload when upstream
  nodes absent from canvas; sets `isPartial` correctly.
- Regression: single-producer source dataset shows empty upstream (no false sources).

**Component**
- `DatasetDetailPanel` renders "Derived from (N)" with cross-dataflow labels.

**Integration/regression**
- End-to-end `whatif-modified-compute` source-dataset case.

## 8. Acceptance Criteria

1. Dataset Details for `computed.whatif-modified-compute@1` shows a **"Derived from"** entry for
   `computed.whatif-data` (its upstream source via `whatif-pool`).
2. Lineage does **not** stop at the immediate producer: chained computed-from-computed and
   cross-dataflow sources appear with correct dataflow labels.
3. Canvas-less catalog page shows backend-resolved sources or a clearly *partial* state.
4. No infinite loop/hang on cyclic or deep chains (cycle guard + depth cap; partial flagged).
5. No regressions in the authoritative-producer display or downstream usage.
