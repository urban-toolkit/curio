## Encapsulation and Source-of-Truth Rules

- Numbered specifications under `../docs/01-...` through `../docs/11-...` are current product/architecture sources. The retained attached-dock and chat-feedback memos add unique current visual guidance. Generated concepts under `../png-concepts/`, `../svg-concepts/`, and `../vectors/` are supporting evidence and are non-canonical where their README marks them stale.
- The KGGraph methodology and examples under `../knowledge-graph/` remain unchanged.
- Agents Catalog-specific Design and Build tracking lives under `dev/kggraph/` so the planning package can evolve independently while preserving KGGraph stage boundaries.
- Implementation work must create modular phase logs beneath `kggraph/Stage-3-Build-Phase/agents-catalog/` as specified by the Build Log index.
- The policy and prompt-governance model in memo `11` supplements the core plan without moving mutable settings, prompt drafts, evaluation evidence, compliance-audit findings, or governance history into immutable manifests. Its implementation and verification must use the same KGGraph traceability chain as catalog/runtime work.
- Memo `12` defines the active lifecycle. Conflicting historical account-installation, attachment-publication/versioning, live-shared-project, and direct node-Explanation planning memos were removed under memo `13`; they are not implementation sources. Current implementation follows immutable definition → explicit account import or catalog source → explicit project template install → private attached instance → allowlisted shared result.
