## Tracking Rules

1. Create an entry before or with the first implementation change for a task.
2. Link every changed module and test to at least one `TASK-*` and `REQ-*`.
3. For every source move, record the old path, new `agents/` path, updated consumers, compatibility adapter (if any), removal commit, and import-boundary evidence.
4. For every prompt-backed agent, record its manifest ID/version, prompt asset paths/digests, input/output contracts, legacy call sites, parity evidence, enablement state, and any unresolved blocker.
5. For every capability change, record semantic ID/contract version, implementing agents, selection rules, compatibility evidence, deprecation/migration state, and proof that prompt filenames remain implementation-only.
6. For every lifecycle/privacy change, record definition/import/project-template/instance IDs and scope, explicit command, ownership, project palette/cache effects, legal transitions, imported-only publication eligibility, and cross-account/project isolation evidence.
7. For every artifact/version/import change, record the exact definition coordinate, bounded staging/extraction, private import record, retained execution/template references, collision behavior, no-auto-install/publish proof, and garbage-collection eligibility. Never record attachment revision as SemVer.
8. For every provider/runtime change, record secret-reference handling, local/remote egress policy, endpoint validation, execution lease/recovery behavior, rollout flag, quota, and redaction evidence.
9. Sharing: no new build (D-0 = B — see `../../14-plan-hardening-and-open-decisions-memo.md`). The agents feature adds no `SharedFlowResult` pipeline/endpoint/viewer and does not retire the existing share route. The only share evidence to record is a regression suite proving the feature introduces no agent-private data (definitions, imports, templates, attachments, prompts, evaluations, audits, settings, provider secrets, transcripts, private IDs) as a new shared surface in Curio's existing flow-sharing.
10. Record design deviations before merge; link the approving ADR/decision.
11. Record failed tests, regressions, partial failures, interrupted work, and rollback work, not only successful outcomes.
12. A phase becomes complete only when its test gate in the development plan passes and evidence is linked.
13. Commits stay focused and update the corresponding log in the same commit when practical.
14. Corrections append a new entry and mark the prior entry superseded; do not erase history.
15. For every settings change, record Account policy, Imported definition, Project agent default, or Attached instance scope; project/template/instance IDs where private; inherited/effective/ceiling values; reset isolation; execution snapshot; authorization; and accessibility evidence.
16. For every cost/quota/resource change, record price/policy revisions, reservation/admission/settlement IDs, retry/child/evaluation charging, concurrency/failure evidence, stable denial/recovery behavior, and proof that lower scopes cannot loosen or grant access.
